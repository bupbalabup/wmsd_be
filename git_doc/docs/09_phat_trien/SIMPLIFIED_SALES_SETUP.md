# Simplified sales — local setup and verification

17 November 2026. Implemented on latest backend main `d146637`, paired frontend `457ac9d`, in `sales-returns-be` / `sales-returns-fe`, branch `codex/simplified-sales-returns`. Earlier Excel/opening changes were carried forward without changing their original worktrees. No commit, push or remote rollout.

1. Review [current API, schema and workflow](../08_api/GOODS_ISSUES.md). Existing records require no backfill; do not change mode markers on legacy documents.
2. Configure the intended local database through the existing environment setup. Run `npm run seed:sync-permissions` to add the existing `delivery_confirmation:confirm` grant to SALES. This is required for existing roles; seed changes alone do not modify a running database.
3. Start API and frontend using their existing development commands. Sales starts at `/orders`; Warehouse creates SALE at `/goods-issues/create` using an active Sales Order.
4. Check customer receipt evidence and undelivered physical receipts on the same phiếu. New customer-return inspection requires no custody bin; accepted receipt must show its CR source and separate receipt code.

Verification uses isolated throwaway databases named `direct_sales_test_<random>` on `mongodb://127.0.0.1:27018/?replicaSet=hieudt-test`. They are created and dropped by `RUN_GOODS_ISSUE_TESTS=1 node --test test/direct-sales.integration.test.js test/goods-issues.integration.test.js`; never point tests at live data. Tested direct issue/post without WIR/OD/picking, exact stock, replay, role checks, source lookup/evidence access, customer receipt versus undelivered race, source caps, CR inspection without custody, acceptance/receipt, SO detail links and legacy issue regressions. Standard backend tests and docs checks are recorded in the change log. Browser layout verification uses synthetic intercepted API data; it does not replace transaction tests or live evidence storage verification.

Existing OTHER, transfer, supplier-return and historical custody APIs retain their original contracts. Direct draft stock is revalidated at post and can become unavailable; cancel/recreate rather than altering posted history. Direct options currently list the 100 most recent open orders.
